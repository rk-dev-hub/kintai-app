# テスト方針・実装計画

## 1. テスト戦略

### 1.1 単体（Vitest）— 最重要

対象と目標カバレッジ:

| モジュール                               | 重点                                                                                      | 目標           |
| ---------------------------------------- | ----------------------------------------------------------------------------------------- | -------------- |
| `aggregation/domain`（日次・週次・月次） | `04` の全ワークド例＋境界（日跨ぎ・深夜端・週境界・締め日 20 日・60h 前後・半休＋実労働） | 分岐 100% 目標 |
| `time-clock/domain`（状態機械）          | 全遷移と不正遷移、日跨ぎ、休憩ネスト                                                      | 100%           |
| `leave/domain`（残数・FIFO 消化・失効）  | 複数付与の消化順、半日、取消戻し                                                          | 100%           |
| `calendar/domain`（休日判定）            | 手動 > 祝日 > 曜日 の優先順位、振替                                                       | 100%           |
| Zod スキーマ                             | 代表的な不正入力                                                                          | 主要ケース     |

- フィクスチャは `tests/fixtures/`（就業規則スナップショット、打刻列パターン）に集約。
- 純粋関数なので DB 不要。高速に回す。

### 1.2 結合（Vitest ＋ テスト用 DB）

- usecase 層を実 Prisma（`kintai_test` スキーマ、`docker compose` の別 DB or 同 DB 別スキーマ）で検証。
- 各テストはトランザクションでロールバック、または `truncate` で分離。
- 対象: `approveCorrection`（打刻列適用→再計算）、`approveLeave`（台帳生成）、
  `closePeriod`/`reopenPeriod`（ロック）、認可（他人データ拒否）。

### 1.3 E2E（Playwright）— 主要 5 シナリオ

1. 従業員が出勤〜休憩〜退勤し当日サマリが正しい。
2. 打刻漏れ → 修正申請 → ADMIN 承認 → 勤怠一覧と月次に反映。
3. 有給申請 → 承認 → 残日数が減り、当日が休暇表示。
4. ADMIN が月次を締める → 従業員の当該期間への申請が不可 → 再オープンで可能に。
5. 月次勤務表を開き CSV / PDF がダウンロードできる（ヘッダ・件数を検証）。

- 認証はストレージステート再利用（`employee.json` / `admin.json` を setup プロジェクトで生成）。
- 前提データは seed ＋ 各シナリオ先頭の API/Action 呼び出しで用意。

### 1.4 CI 相当（ローカル品質ゲート）

`pnpm verify` = `typecheck && lint && test`（単体のみ。結合テストは含めない）。E2E は `pnpm test:e2e` で分離。
lefthook: pre-commit（差分ファイルの lint/format、typecheck）／pre-push（`pnpm test`）。

### 集計の既知の簡略化（`docs/04` に詳細）

- 日次の端数丸めは行わない（昭 63.3.14 基発 150 号）。`roundingUnitMinutes` は月次丸め用に予約。
- 休憩不足判定（労基法 34 条）は「拘束時間」基準（本来は労働時間基準）。警告フラグのみ。
- 半休の「所定の中央」は始業・終業の単純中点で、休憩を勘案しない。
- 月 60h 超判定は暦月ではなく締め期間で行う（締め日設定に追従）。
- PDF は表示に使う文言のみを収録したサブセット日本語フォント（Noto Sans JP, SIL OFL）を同梱。氏名・申請理由など任意入力の自由文字は収録対象外のため PDF には表示しない（社員番号のみ。氏名まで必要な場合は日別 CSV / 画面の勤務表を使う）。
